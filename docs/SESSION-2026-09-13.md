## What fixed the timeout

The old Fabric CONFIGURATION sender was not sufficient for the Forge 1.7.10 serverbound handshake path.

`alpha.6` now uses a direct ViaVersion serverbound PLAY-pipeline transport:

```text
LegacyForgeBridge FML state machine
→ ViaVersion UserConnection
→ Serverbound CUSTOM_PAYLOAD
→ Protocol1_12_2To1_13
→ channel alias reverse mapping
→ FML|HS / REGISTER
→ legacy 1.7.10 server
```

Inbound Forge packets are still received through the translated Fabric CONFIGURATION / PLAY payload receivers.

## Known issues after entering PLAY

### 1. FML runtime packets are not implemented yet

The current trace labels PLAY-channel `FML` discriminator `0x03` incorrectly as `ModIdData`.

Correct Forge 1.7.10 FML runtime codec:

```text
0 = CompleteHandshake
1 = OpenGui
2 = EntitySpawnMessage
3 = EntityAdjustMessage
```

The test session receives many `EntityAdjustMessage` packets after joining. They are currently logged but not applied.

`EntityAdjustMessage` contains:

```text
entityId
serverX
serverY
serverZ
```

This is a likely contributor to entity/player visual or positional oddities seen after joining.

### 2. Player appearance still needs diagnosis

The user reported their own player appearance looks wrong.

Need to distinguish between:

- entity position / interpolation / rotation problems;
- skin/model problems (Steve/Alex arms, skin layers, cape, texture, profile properties).

Do not assume these are the same issue.

### 3. Legacy chat / translation keys can appear in English

Observed examples include old 1.7.10-era messages such as achievement and game-mode messages.

Likely cause: modern 1.21.11 no longer contains some legacy translation keys / old achievement system keys, so translated components fall back to English or otherwise lose the old localized text.

Need a session-only legacy translation fallback, not a global replacement of the modern language table.

## Important guardrails

- Vanilla 1.7.10 protocol translation remains ViaFabricPlus/ViaVersion responsibility.
- LegacyForgeBridge owns Forge/FML behavior, registry identity, converted mod compatibility and legacy runtime semantics.
- Do not assume modern raw registry IDs equal Forge 1.7.10 numeric IDs.
- Do not globally mutate the modern Minecraft registry or language tables.
- Keep `legacyforgebridge.log` as one file per Minecraft launch, truncated on startup.
- Continue using direct ViaVersion transport for Forge/FML serverbound handshake/runtime packets when required by legacy PLAY semantics.
