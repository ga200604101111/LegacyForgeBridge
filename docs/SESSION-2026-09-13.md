## FML runtime bridge

Handshake (`FML|HS`) and runtime (`FML`) codecs remain separate.

```text
0 = CompleteHandshake
1 = OpenGui
2 = EntitySpawnMessage
3 = EntityAdjustMessage
```

`EntityAdjustMessage` keeps original Forge semantics and updates the modern packet-position baseline instead of teleporting the entity:

```text
serverPosX / 32.0
serverPosY / 32.0
serverPosZ / 32.0
→ Entity.syncPacketPositionCodec(x, y, z)
```

Live testing previously confirmed real PLAY `EntityAdjustMessage` packets are decoded and applied successfully.

```text
LegacyForgeBridge owns:

LegacyForgeBridge does NOT own:
```

## Legacy translation architecture

The server sends locale-independent keys such as:

```text
commands.help.header
commands.achievement.usage
commands.clear.usage
commands.effect.usage
disconnect.loginFailedInfo.serversUnavailable
```

The client language should decide the final wording. LFB must never reverse-match a final English sentence back into a key.

### Language resources

The user supplied original Minecraft/Forge 1.7.10 `en_US.lang` and `zh_TW.lang` files.

Only selected legacy keys are bundled as build inputs under:

```text
assets/lfb-minecraft/legacy-lang/en_us/*.lang
assets/lfb-minecraft/legacy-lang/zh_tw/*.lang
assets/lfb-forge/legacy-lang/en_us/*.lang
assets/lfb-forge/legacy-lang/zh_tw/*.lang
```

At build time they become collision-free modern aliases:

```text
assets/lfb-minecraft/lang/en_us.json
assets/lfb-minecraft/lang/zh_tw.json
assets/lfb-forge/lang/en_us.json
assets/lfb-forge/lang/zh_tw.json
```

Example keys:

```text
lfb.minecraft.commands.help.header
lfb.minecraft.commands.clear.usage
lfb.forge.commands.forge.usage
```

The alias prefix means the old catalogue cannot globally replace normal 1.21.11 translations.

### Hard exclusion: legacy content names

The following remain owned by ViaVersion + modern Minecraft:

```text
item.*
ordinary tile.* / block.*
entity.*
container.*
options.*
forge.configgui.*
fml.configgui.*
```

A 1.7.10 connection must not make modern item/block names consume the old 1.7.10 language table. Nested item/block names inside a preserved outer server message also remain Via-owned.

## alpha.10 runtime failure

alpha.10 passed compile/test CI but failed on the live client because ViaFabricPlus 4.4.15 relocates Gson:

```text
compile/API:
com.google.gson.JsonObject

runtime:
com.viaversion.viaversion.libs.gson.JsonObject
```

The original `ViaComponentTranslationMixin` callback descriptor used the unshaded type and Mixin rejected it.

## alpha.11 startup fix

alpha.11 changed the JSON callback boundary to:

```text
@Coerce Object
→ ViaJsonObjectAccess
→ reflective get/getAsString/addProperty
```

Regression tests require that the compiled JSON callback descriptors contain neither the unshaded nor the Via-relocated Gson package.

Live testing confirmed this fixed the startup crash.

### Root cause: ViaLegacy is earlier than ViaVersion

The lossy rewrite does not start at the later `ComponentRewriterBase` hook.

ViaLegacy's first protocol boundary:

```text
r1_7_6_10 -> r1_8
net.raphimc.vialegacy...rewriter.TextRewriter
```

contains an English `TRANSLATIONS` table and performs:

```text
TranslationComponent key
→ if TRANSLATIONS contains key
→ setKey(English fallback string)
```

Known entries include:

```text
commands.achievement.usage
commands.clear.usage
commands.effect.usage
commands.time.usage
commands.tp.usage
commands.scoreboard.*
commands.spawnpoint.usage
commands.gamerule.usage
disconnect.loginFailedInfo.serversUnavailable
```

By the time the downstream ViaVersion component rewriter sees the component, the original key has already been destroyed. Therefore preserving the key only at the ViaVersion layer is too late for this class of messages.

## alpha.12 fix — preserve at the earliest ViaLegacy boundary

alpha.12 adds `ViaLegacyTextRewriterMixin`.

Before ViaLegacy's `TextRewriter.toClient(UserConnection, String)` parses the JSON, LFB recursively changes only selected legacy `translate` keys to collision-free aliases:

```text
{"translate":"commands.clear.usage"}
        ↓
{"translate":"lfb.minecraft.commands.clear.usage"}
        ↓
ViaLegacy TextRewriter
        ↓
no English TRANSLATIONS match
        ↓
all normal ViaLegacy/ViaVersion component conversion continues
        ↓
Minecraft language stack
        ↓
/clear <玩家> [物品] [物品數據值]
```

This is **not** English reverse matching. It preserves semantic identity before ViaLegacy destroys it.

`LegacyJsonTranslationAliaser`:

- parses only the JSON String boundary;
- recursively handles nested `with` / `extra` components;
- changes only selected `translate` keys;
- keeps item/block/entity/container keys unchanged;
- returns the original string unchanged if parsing fails.

The existing downstream `ViaComponentTranslationMixin` remains as a second preservation layer for translation components that reach later ViaVersion stages without passing through this ViaLegacy chat rewrite.

`gui.toMenu` is also included as an explicit legacy presentation key so a legacy disconnect/menu component can use the supplied 1.7.10 wording without globally replacing modern GUI translations.

## Guardrails

- Keep `FML|HS` handshake and `FML` runtime codecs separate.
- Do not assume modern registry raw IDs equal Forge 1.7.10 numeric IDs.
- Do not globally mutate modern registries or the modern Minecraft language table.
- Do not translate `EntityAdjustMessage` into direct entity teleportation.
- Do not intercept or replace player skin resolution in LegacyForgeBridge.
- Do not reverse-match Via/ViaLegacy English strings back into translation keys.
- Preserve legacy translation identity before the earliest lossy rewrite.
- Do not route item/block/entity/container names through the 1.7.10 catalogue.
- Do not bind Mixin callback descriptors to dependency classes that ViaFabricPlus may relocate/shade.
- Keep `legacyforgebridge.log` as one file per Minecraft launch.
