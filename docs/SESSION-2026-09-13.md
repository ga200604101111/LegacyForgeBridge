## alpha.7 — FML runtime bridge

A dedicated runtime codec was added for the legacy `FML` channel, separate from `FML|HS`.

Runtime discriminators:

```text
0 = CompleteHandshake
1 = OpenGui
2 = EntitySpawnMessage
3 = EntityAdjustMessage
```

`EntityAdjustMessage` uses original Forge semantics and updates the packet-position baseline rather than teleporting the entity:

```text
serverPosX / 32.0
serverPosY / 32.0
serverPosZ / 32.0
→ Entity.syncPacketPositionCodec(x, y, z)
```

Live testing confirmed real PLAY `EntityAdjustMessage` packets are decoded and applied successfully.

## Skin ownership conclusion

Minecraft 1.7.10 loads skins client-side through its `SkinManager` / `MinecraftSessionService`. The user also intends to use a custom skin mod that replaces/corrects skin resolution.

`alpha.8` briefly intercepted `AbstractClientPlayer#getSkin()`, but that approach was retired.

```text
LegacyForgeBridge owns:
- Forge/FML handshake
- Forge/FML runtime semantics
- legacy registry identity
- converted-mod compatibility

LegacyForgeBridge does NOT own:
- skin downloading/caching
- skin URLs
- Steve/Alex/slim selection
- cape skin-service behavior
- custom skin mod behavior
```

## Why legacy server messages became English

The Forge 1.7.10 server sends vanilla message translation keys such as:

```text
commands.help.header
commands.help.footer
commands.achievement.usage
```

The server does not send pre-localized Chinese text for those original vanilla messages.

ViaVersion rewrites translations while crossing protocol boundaries. In particular, its 1.12.2→1.13 mapping contains removed legacy keys with an English inline fallback. Example:

```text
-commands.help.header=--- Showing help page %s of %s (/help <page>) ---
```

Via's component rewriter replaces the old `translate` key with that English fallback before the 1.21.11 client language system can see the original key.

Via also has an older 1.11→1.12 achievement/stat compatibility rewriter containing English fallback values. Therefore fixing only `/help` or reverse-matching final English sentences is not a robust solution.

## alpha.10 — session-scoped legacy message translation

### Design rule

Do **not** reverse-match an English sentence back to a translation key.

Instead, while ViaFabricPlus targets Minecraft 1.7.6-1.7.10:

```text
1.7.10 server component
translate = original legacy key
        ↓
ViaVersion component/protocol conversion
        ↓
LFB restores selected original message key after each Via component rewriter
        ↓
1.21.11 TranslatableContents
        ↓
LFB private 1.7.10 message catalogue
        ↓
selected client language (zh_tw / en_us)
```

ViaVersion still owns all non-language protocol conversion, including component shape, nested arguments, hover/click data, NBT representation and normal content key mapping.

### Message keys only — content names are deliberately excluded

The legacy translation layer preserves server/message-oriented keys such as:

```text
commands.*
chat.type.*
chat.stream.*
death.*
multiplayer.player.*
multiplayer.disconnect.*
disconnect.*
achievement.*
stat.*
stats.tooltip.*
gameMode.*
```

Plus a small set of old bed-status messages and explicit Forge server-message keys.

The following are **not** preserved by LFB and continue through ViaVersion + Minecraft 1.21.11 normally:

```text
item.*
ordinary tile.* / block.*
entity.*
container.*
options.*
forge.configgui.*
fml.configgui.*
```

This is an explicit regression requirement: a 1.7.10 connection must not make modern item/block names consume the old 1.7.10 language catalogue.

Nested content names inside an old server message also remain modern-mapped. For example, LFB may preserve the outer `commands.give.success` message while Via still maps a nested item-name component normally.

### Private language catalogue

The user supplied the original language resources:

```text
minecraft/lang/en_US.lang
minecraft/lang/zh_TW.lang
forge/lang/en_US.lang
forge/lang/zh_TW.lang
```

LFB filters only the message-oriented entries and bundles them privately under:

```text
assets/lfb-minecraft/legacy-lang/en_us/*.lang
assets/lfb-minecraft/legacy-lang/zh_tw/*.lang
assets/lfb-forge/legacy-lang/en_us/*.lang
assets/lfb-forge/legacy-lang/zh_tw/*.lang
```

These intentionally do **not** use the standard `assets/<namespace>/lang/*.json` path. Minecraft 1.21.11 merges normal language resources from all namespaces into one global translation map; loading the complete 1.7.10 language files there could overwrite same-key modern UI/content translations even outside the intended message path.

The private parser mirrors the original 1.7.10 language parser:

- UTF-8;
- ignore blank lines and `#` comments;
- split on the first `=`;
- normalize numeric `%d/%f` placeholders to `%s` while preserving positional indexes.

Filtered source counts currently bundled:

```text
Minecraft en_US: 428 message entries
Minecraft zh_TW: 423 message entries
Forge en_US:       9 message entries
Forge zh_TW:       9 message entries
```

The filtered resources are generated directly from the supplied 1.7.10 files; old item/block names are not included in the private catalogue.

### Implementation points

- `ViaComponentTranslationMixin`
  - targets ViaVersion `ComponentRewriterBase`;
  - snapshots only whitelisted message `translate` keys;
  - restores those keys after each JSON/NBT component rewrite;
  - leaves all other Via translation mappings untouched.

- `TranslatableContentsMixin`
  - redirects the final language lookup for selected legacy message keys only;
  - falls back to normal modern `Language` behavior when no legacy message exists or the target is not 1.7.10.

- `LegacyLanguageCatalog`
  - private session-aware language catalogue;
  - reads `Minecraft.options.languageCode`;
  - selected language first, then `en_us` fallback.

## Guardrails

- Keep `FML|HS` handshake and `FML` runtime codecs separate.
- Do not assume modern registry raw IDs equal Forge 1.7.10 numeric IDs.
- Do not globally mutate modern registries or the modern Minecraft language table.
- Do not translate `EntityAdjustMessage` into direct entity teleportation.
- Do not intercept or replace player skin resolution in LegacyForgeBridge.
- Do not reverse-match Via's English strings back into translation keys.
- Preserve only legacy **message** translation keys; do not route item/block/entity/container names through the 1.7.10 catalogue.
- Keep `legacyforgebridge.log` as one file per Minecraft launch.
