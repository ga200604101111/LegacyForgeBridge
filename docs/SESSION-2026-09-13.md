## FML runtime bridge

Handshake (`FML|HS`) and runtime (`FML`) codecs remain separate.

```text
0 = CompleteHandshake
1 = OpenGui
2 = EntitySpawnMessage
3 = EntityAdjustMessage
```

`EntityAdjustMessage` keeps original Forge semantics and updates the modern packet-position baseline instead of teleporting the entity:

```text
serverPosX / 32.0
serverPosY / 32.0
serverPosZ / 32.0
→ Entity.syncPacketPositionCodec(x, y, z)
```

Live testing previously confirmed real PLAY `EntityAdjustMessage` packets are decoded and applied successfully.

## Legacy translation architecture

The intended rule is that the 1.7.10 semantic identity survives protocol translation and the client language chooses the final wording.

LFB must never reverse-match a final English sentence back into a translation key.

### Language resources

The user supplied original Minecraft/Forge 1.7.10 `en_US.lang` and `zh_TW.lang` files.

Only selected legacy presentation/message keys are bundled as build inputs under:

```text
assets/lfb-minecraft/legacy-lang/en_us/*.lang
assets/lfb-minecraft/legacy-lang/zh_tw/*.lang
assets/lfb-forge/legacy-lang/en_us/*.lang
assets/lfb-forge/legacy-lang/zh_tw/*.lang
```

At build time they become collision-free modern aliases:

```text
assets/lfb-minecraft/lang/en_us.json
assets/lfb-minecraft/lang/zh_tw.json
assets/lfb-forge/lang/en_us.json
assets/lfb-forge/lang/zh_tw.json
```

Example aliases:

```text
lfb.minecraft.commands.help.header
lfb.minecraft.commands.clear.usage
lfb.minecraft.gameMode.changed
lfb.forge.commands.forge.usage
```

The alias prefix means the old catalogue cannot globally replace normal 1.21.11 translations.

### Hard exclusion: legacy content names

The following remain owned by ViaVersion + modern Minecraft:

```text
item.*
ordinary tile.* / block.*
entity.*
container.*
options.*
forge.configgui.*
fml.configgui.*
```

A 1.7.10 connection must not make modern item/block names consume the old 1.7.10 language table. Nested item/block names inside a preserved outer server message also remain Via-owned.

## alpha.10 runtime failure

alpha.10 passed compile/test CI but failed on the live client because ViaFabricPlus 4.4.15 relocates Gson:

```text
compile/API:
com.google.gson.JsonObject

runtime:
com.viaversion.viaversion.libs.gson.JsonObject
```

The original `ViaComponentTranslationMixin` callback descriptor used the unshaded type and Mixin rejected it.

## alpha.11 startup fix

alpha.11 changed the JSON callback boundary to:

```text
@Coerce Object
→ ViaJsonObjectAccess
→ reflective get/getAsString/addProperty
```

Regression tests require that the compiled JSON callback descriptors contain neither the unshaded nor the Via-relocated Gson package.

Live testing confirmed this fixed the startup crash.

## alpha.11 live translation gap

The same live test showed that `/help` was only partially correct. Header/footer were translated, but several command usage entries stayed English.

### Root cause: ViaLegacy's early English table

ViaLegacy's first protocol boundary:

```text
r1_7_6_10 -> r1_8
net.raphimc.vialegacy...rewriter.TextRewriter
```

contains an English `TRANSLATIONS` table and replaces old translation keys before later ViaVersion component rewriters run.

Known examples include:

```text
commands.achievement.usage
commands.clear.usage
commands.effect.usage
commands.time.usage
commands.tp.usage
commands.scoreboard.*
commands.spawnpoint.usage
commands.gamerule.usage
disconnect.loginFailedInfo.serversUnavailable
```

## alpha.12 fix — preserve before ViaLegacy's lossy table

alpha.12 adds `ViaLegacyTextRewriterMixin`.

Before ViaLegacy parses the 1.7.10 JSON component, LFB recursively changes only selected old `translate` keys to collision-free aliases:

```text
{"translate":"commands.clear.usage"}
        ↓
{"translate":"lfb.minecraft.commands.clear.usage"}
        ↓
ViaLegacy TextRewriter
        ↓
no English TRANSLATIONS match
        ↓
normal ViaLegacy/ViaVersion conversion
        ↓
Minecraft language stack
        ↓
/clear <玩家> [物品] [物品數據值]
```

This is semantic preservation before loss, not English reverse matching.

Live alpha.12 testing confirmed this class of `/help` usage translations was improved, but game-mode-change feedback was still English.

## alpha.12 live game-mode gap

Observed on the real 1.7.10 server:

```text
ViaFabricPlus/LFB result:
Your game mode has been updated

original 1.7.10 zh_TW result:
您的遊戲模式已更新
```

The supplied 1.7.10 language file confirms:

```text
gameMode.changed=您的遊戲模式已更新
```

### Root cause: this message is not a translation component from the server

ViaLegacy's `Protocolr1_7_6_10Tor1_8` handles the old `GAME_EVENT` packet. For reason `3` (game-mode change), ViaLegacy creates a new 1.8 `CHAT` packet itself and feeds a literal English sentence into `LEGACY_TO_JSON`:

```text
GAME_EVENT reason 3
        ↓
ViaLegacy creates ClientboundPackets1_8.CHAT
        ↓
LEGACY_TO_JSON(literal English)
        ↓
chat packet is sent after the 1.7.10 -> 1.8 protocol stage
```

Because the synthetic packet already contains literal text, neither alpha.12's early `TranslationComponent` aliaser nor the later ViaVersion component-preservation hook can recover a key. There is no key left to preserve.

## alpha.13 fix — restore the original semantic key at the synthetic-packet source

alpha.13 adds `ViaLegacyGameModeMessageMixin`.

The hook targets ViaLegacy's first `LEGACY_TO_JSON` transformer for the exact 1.7.10 -> 1.8 protocol. It does **not** inspect the English sentence. Instead it checks the transformer's packet context:

```text
ViaLegacy LEGACY_TO_JSON transformer
+ target protocol is 1.7.10
+ packet direction = CLIENTBOUND
+ packet type name = CHAT
        ↓
this is the synthetic game-mode-change presentation packet in this protocol path
        ↓
return {"translate":"lfb.minecraft.gameMode.changed"}
```

Other uses of the same transformer, such as legacy window/tab-list presentation text, keep ViaLegacy's normal behavior because their packet type is not `CHAT`.

The final client language lookup therefore resolves:

```text
zh_tw → 您的遊戲模式已更新
en_us → Your game mode has been updated
```

without matching the English output string.

- semantic `CHAT` + `gameMode.changed` constants present;

## Guardrails

- Keep `FML|HS` handshake and `FML` runtime codecs separate.
- Do not assume modern registry raw IDs equal Forge 1.7.10 numeric IDs.
- Do not globally mutate modern registries or the modern Minecraft language table.
- Do not translate `EntityAdjustMessage` into direct entity teleportation.
- Do not intercept or replace player skin resolution in LegacyForgeBridge.
- Do not reverse-match Via/ViaLegacy English strings back into translation keys.
- Preserve legacy translation identity before the earliest lossy rewrite.
- For ViaLegacy-synthesized presentation packets, restore semantics from packet/handler context rather than final English text.
- Do not route item/block/entity/container names through the 1.7.10 catalogue.
- Do not bind Mixin callback descriptors to dependency classes that ViaFabricPlus may relocate/shade.
- Keep `legacyforgebridge.log` as one file per Minecraft launch.
