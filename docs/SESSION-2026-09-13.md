## alpha.7 — Forge/FML runtime bridge

`alpha.7` added the first Forge 1.7.10 runtime layer without modifying the working `FML|HS` state machine.

### Runtime codec

The legacy `FML` runtime channel is separate from `FML|HS` because the discriminator values overlap but mean different things:

```text
0 = CompleteHandshake
1 = OpenGui
2 = EntitySpawnMessage
3 = EntityAdjustMessage
```

Current behavior:

- `CompleteHandshake`: decoded and accepted.
- `OpenGui`: fully decodes `windowId`, `modId`, `modGuiId`, `x`, `y`, `z`; converted-mod GUI dispatch remains future work.
- `EntitySpawnMessage`: decodes the stable header while keeping legacy DataWatcher / throwable / mod-specific tail opaque.
- `EntityAdjustMessage`: decoded and applied during PLAY.

### EntityAdjust semantic bridge

Forge 1.7.10 updates `serverPosX/Y/Z`; it does not directly teleport the rendered entity.

Minecraft 1.21.11 stores the equivalent relative-movement baseline in the entity packet-position `VecDeltaCodec`, so the bridge maps:

```text
serverX / 32.0
serverY / 32.0
serverZ / 32.0
    ↓
Entity.syncPacketPositionCodec(x, y, z)
```

It deliberately does not call `setPos`, `snapTo`, or teleport APIs.

## alpha.8 — legacy local-player skin/profile bridge

Because the remaining symptom affects only the local player, `alpha.8` moves diagnosis/fallback to the modern player skin path.

Minecraft 1.21.11 renders a client player skin through:

```text
AbstractClientPlayer#getSkin
→ PlayerInfo
→ GameProfile
→ SkinManager
→ PlayerSkin
```

Old protocol translation can construct the local modern `PlayerInfo` differently from remote player-list entries. If the local translated `GameProfile` lacks the packed `textures` property, modern Minecraft falls back to a default player appearance even though the client already fetched its authenticated Mojang profile at startup.

### Implemented behavior

Added a client-only local-player fallback active only while ViaFabricPlus targets Forge-era Minecraft 1.7.6-1.7.10 sessions.

The bridge compares:

- translated session `PlayerInfo` / `GameProfile`;
- Minecraft's authenticated startup `profileFuture` result.

It uses the authenticated profile skin only when:

```text
authenticated profile has textures
AND
(session profile ID differs OR session profile has no textures)
```

If the translated local profile already has a matching identity and texture property, vanilla skin lookup is retained.

Remote players are never modified. Non-legacy sessions are never modified. Texture property values and authentication tokens are never written to the trace.

### Diagnostic trace

The next live test should produce one of these decisions:

```text
Legacy local-player authenticated skin fallback enabled ...
```

or:

```text
Legacy local-player skin profile is complete; vanilla skin lookup retained ...
```

or, if Mojang profile resolution itself has no texture:

```text
Legacy local-player skin fallback unavailable: authenticated profile has no textures ...
```

The fallback trace also records safe metadata such as session/authenticated texture counts, profile-ID match, model type, secure flag, and resolved texture resource path.

## Important guardrails

- Vanilla 1.7.10 protocol translation remains ViaFabricPlus/ViaVersion responsibility.
- LegacyForgeBridge owns Forge/FML behavior, registry identity, converted mod compatibility and legacy runtime semantics.
- Keep handshake (`FML|HS`) and runtime (`FML`) codecs separate.
- Do not assume modern raw registry IDs equal Forge 1.7.10 numeric IDs.
- Do not globally mutate modern registry or language tables.
- Do not translate `EntityAdjustMessage` into a direct teleport.
- Do not globally override player skins; alpha.8 fallback is local-player + legacy-session + evidence gated.
- Keep `legacyforgebridge.log` as one file per Minecraft launch, truncated on startup.
