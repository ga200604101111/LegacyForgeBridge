# Session 2026-09-16 — Explosion decay formula and Forge event boundary

Branch: `feature/generic-conversion-bamboo-corpus2`

## Purpose

The static block-drop readiness slice intentionally left explosion runtime unmapped. This slice
separates two different questions:

1. Is the **drop probability formula** equivalent between Minecraft 1.7.10 and Minecraft 1.21.11?
2. Can source Forge explosion events or modern explosion interaction modes change whether that
   formula actually applies?

The formula is now version-locked and proven. Full explosion runtime is still deliberately gated.

## Exact legacy formula

MCP 908 (Minecraft 1.7.10) `Explosion` passes the following chance into the Block drop path for each
affected block whose `canDropFromExplosion` result is true:

```text
1.0F / explosionSize
```

The base 1.7.10 `Block.dropBlockAsItemWithChance` path accepts an item when:

```text
world.rand.nextFloat() <= chance
```

Therefore the source-side decay condition is exactly:

```text
random.nextFloat() <= 1.0F / explosionSize
```

## Exact modern decay formula

Minecraft 1.21.11 `ExplosionCondition` (`minecraft:survives_explosion`) reads
`LootContextParams.EXPLOSION_RADIUS` and evaluates:

```text
float probability = 1.0F / explosionRadius;
return random.nextFloat() <= probability;
```

For `DESTROY_WITH_DECAY`, `BlockBehaviour.onExplosionHit` supplies:

```text
LootContextParams.EXPLOSION_RADIUS = explosion.radius()
```

The probability expression and comparison operator are therefore equivalent for the modern decay
interaction.

The readiness artifact records:

```text
explosionDecayFormulaProofVersion = mcp908-1.7.10-to-minecraft-1.21.11-survives-explosion
explosionDecayFormulaProofComplete = true
modernExplosionDecayCondition = minecraft:survives_explosion
```

when the source plan carries the proven `inverse_explosion_size_1_7_10` mode.

## Forge 1.7.10 ExplosionEvent boundary

Forge 1.7.10 defines:

```text
net.minecraftforge.event.world.ExplosionEvent.Start
net.minecraftforge.event.world.ExplosionEvent.Detonate
```

`Start` is cancelable and can stop the explosion. `Detonate` exposes mutable affected-block and
entity lists.

The runtime-readiness pass now scans the source JAR with `LegacyEventAnalyzer` and fail-closes when a
relevant handler is registered on the Forge bus (or an unresolved/unknown bus). It includes handlers
whose declared event parameter is:

```text
ExplosionEvent.Start
ExplosionEvent.Detonate
ExplosionEvent
cpw.mods.fml.common.eventhandler.Event
```

The parent `ExplosionEvent` and generic FML `Event` forms are included because Forge's event bus uses
inheritance; a source handler does not need to declare the leaf class to observe the explosion.
Handlers proven to be registered only on the FML bus are not treated as Forge explosion handlers.

The readiness sidecar now records:

```text
sourceExplosionEventFree
explosionEventHandlerCount
explosionEventHandlers
explosionAffectedSetSourceProofComplete
eventAnalysisDiagnostics
```

Any unresolved event-analysis diagnostic also keeps absence unproven.

## Remaining modern interaction boundary

Minecraft 1.21.11 can choose either:

```text
DESTROY_WITH_DECAY
DESTROY
```

for block/TNT/mob explosions depending on modern gamerules. `EXPLOSION_RADIUS` is only attached to the
loot context for `DESTROY_WITH_DECAY`. Under `DESTROY`, `minecraft:survives_explosion` sees no radius
and returns true.

Minecraft 1.7.10's affected-block drop path always supplies the `1.0F / explosionSize` chance when it
runs. A plain modern loot table using `survives_explosion` therefore cannot yet be claimed equivalent
for **all** modern explosion interaction modes.

The readiness artifact consequently keeps:

```text
explosionInteractionCoverageComplete = false
explosionRuntimeMappingReady = false
explosionRuntimeBlocker = modern-explosion-destroy-without-decay-context-proof-pending
```

This is now the primary modern explosion-runtime mapping boundary after source event absence and the
probability formula have been separated.
