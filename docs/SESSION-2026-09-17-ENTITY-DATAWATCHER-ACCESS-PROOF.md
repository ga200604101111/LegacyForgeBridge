# 2026-09-17 — Entity DataWatcher direct source-lineage access proof

## Scope

This slice follows the generic entity registration/DataWatcher-definition proof from converter revision `2026-09-17.60`. It inventories and type-checks direct DataWatcher reads/writes declared on the registered source entity lineage before any `SynchedEntityData` runtime is generated.

Converter revision: `2026-09-17.61`.

## Proven source operations

`LegacyEntityDataWatcherAccessAnalyzer` starts only from entity registrations already accepted by `LegacyEntityDataWatcherAnalyzer`. It scans methods declared on the registered source entity and source-owned superclasses and accepts direct watcher access only when:

- the receiver is proven as `this.dataWatcher`, either through the inherited field or `getDataWatcher` / `func_70096_w`;
- the index is a constant;
- the index was defined by the already-proven source watcher schema;
- typed getter kind matches the definition (`byte`, `short`, `int`, `float`, `string`);
- `updateObject` / `func_75692_b` writes a wrapper/string value whose source type matches the definition.

The SRG getter surface is pinned to the Forge 1.7.10 DataWatcher contract:

- `func_75683_a(int)` -> byte;
- `func_75693_b(int)` -> short;
- `func_75679_c(int)` -> int;
- `func_111145_d(int)` -> float;
- `func_75681_e(int)` -> String;
- `func_75692_b(int,Object)` -> update.

MCP aliases for the same calls are also accepted.

## Fail-closed boundary

The direct lineage proof remains closed when source entity methods contain:

- a dynamic watcher read/write index;
- access to a watcher index not defined by the source-owned schema;
- getter/write type mismatch;
- ItemStack watcher access;
- `setObjectWatched` / force-dirty semantics;
- DataWatcher definitions outside `entityInit`;
- any other unsupported direct DataWatcher call.

This intentionally avoids pretending that the legacy watcher transport is equivalent to modern synchronized entity data before every used operation has a mapping.

## Materialized IR

`LegacyEntityDataWatcherAccessPass` writes:

- `legacyforgebridge/entity-datawatcher-access.json`
- schema version 1

Each admitted rule records the modern entity identity inherited from the definition sidecar plus every proven direct read/write callsite. The payload states:

- `sourceLineageAccessSurfaceComplete=true` for the bounded direct lineage scan;
- `reachableHelperClosureComplete=false` because helper/call-graph closure is a later proof gate;
- `runtimeImplementationWired=false` because no modern entity runtime is generated by this slice.

The generic profile now runs:

1. generic registry/content identity;
2. entity registration/DataWatcher definition proof;
3. direct entity-lineage DataWatcher access proof;
4. later independent family passes.

## Regression coverage
